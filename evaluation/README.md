# TripSage 公开评测集

`cases.jsonl` 是依据项目历史评测口径重新整理的公开回归集，用于展示评测方法和支持后续复跑，不等同于开发阶段使用的原始测试数据。

## 数据构成

| 模块 | 数量 | 主要检查项 |
|---|---:|---|
| `intent` | 400 | 主意图、Agent 调度、城市/日期/时长等实体 |
| `rag` | 250 | 检索资料、主题命中、关键概念与来源标注 |
| `preference_memory` | 150 | 偏好新增、覆盖和查询 |
| `itinerary` | 120 | 必要模块、约束满足和方案完整性 |
| `tool_routing` | 80 | 天气、航班、高铁、酒店工具选择与降级 |
| 合计 | 1000 | — |

数据按模块分层划分为 700 条开发集和 300 条保留测试集。开发集用于提示词、路由和规则迭代；保留测试集应在版本冻结后统一运行，避免根据测试结果继续调参。

## 字段说明

- `id`：稳定的样本编号。
- `module`：评测模块。
- `split`：`dev` 或 `test`。
- `input`：用户输入。
- `expected`：结构化期望结果。不同模块拥有不同字段。
- `tags`：用于聚合 Bad Case 的标签。

该数据集由模板与组合条件生成，重点覆盖同义表达、约束组合和业务边界，不代表真实用户请求的自然分布。正式评测时应固定模型版本、提示词版本和采样参数，并对 RAG 答案与行程质量进行人工复核。

## 生成与校验

```bash
node evaluation/generate-dataset.mjs
node evaluation/validate-dataset.mjs
```

生成脚本是数据集的可追溯来源；校验脚本检查总量、模块分布、开发/测试划分以及 ID 和输入唯一性。
